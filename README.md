# 鲜厨记

一个以 HTML、CSS、JavaScript 为核心实现的智能家庭食材存储与烹饪助手。

## 已实现功能

- 食材仓库：添加、编辑、删除、搜索、分类与存储位置筛选
- 家庭采购动态：添加食材时可选择“我 / 家庭成员 A / 家庭成员 B”，仓库记录食材、数量、存放位置和时间；一周采购清单入库也会留下记录。登录后可在同一账号的设备之间同步，家庭成员之间尚未共享账号数据
- FoodHub：预置五条使用现有菜品照片的演示帖及评论。帖子横向铺满内容区，点击悬浮加号可在当前页发布分享，也可点赞和评论；已登录时帖子与互动随个人账号同步，但尚未连接跨账号的在线社区
- 图片导入入库：图片预览、文件名演示匹配、名称/分类/存储位置建议与入库前核对
- 新鲜度提醒：根据到期日期自动判断新鲜、临期、当天到期和已过期
- 今日搭配灵感：根据现有库存推荐少量补购即可完成的菜品
- COOK：优先匹配已有菜谱，按库存缩放小份用量；常见肉、蛋、豆腐和蔬菜的新组合可给出本地做法。支持按菜名搜索做法，收藏菜谱可跳转查看；牛奶与水果可组合奶昔，选中至少三种水果可组合对应的水果拼盘
- 一周食谱：按周一至周日安排早餐、午餐和晚餐共 21 餐，按餐别推荐并汇总采购食材，勾选已购后可加入仓库
- 烹饪记录：完成时核对实际食材用量，确认后再扣减库存
- 我的菜谱：浏览收藏菜谱、最近生成记录与菜谱详情
- 数据持久化：未登录时使用浏览器 localStorage；登录后通过 Node.js 接口保存到 MySQL
- 响应式界面：适配桌面、平板与手机宽度

## 食材视觉素材

侧边栏使用 `assets/sidebar-foods.svg` 展示番茄、牛油果、牛奶、面包、青椒、柠檬和鸡蛋的简洁静物插画，配文为“新鲜食材，认真管理”。界面中的个人名称为“鲜小厨”。

`assets/foods/` 中的生菜、豆腐、土豆、洋葱、虾仁、猪排、五花肉、鸡胸肉、排骨和肥牛卷均由用户提供的原图抠出，并加了白色贴纸边。番茄、鸡蛋和牛奶沿用此前生成的图片。图片按食材名称精确映射，未提供图片的食材继续使用带白边的图标。`tools/prepare_food_cutouts.py` 记录了原图裁切和抠图参数；重新处理时需确保原始附件仍在本机临时目录。

第二批用户图片还包括草莓、面包、猕猴桃、樱桃、蓝莓、荔枝、苹果、柠檬、李子、西瓜、桃子、馒头、挂面、大米、胡萝卜、小米、红豆、绿豆、黄豆、花生、蘑菇和玉米。生米图片只对应“大米”；杏鲍菇原图在系统中作为“蘑菇”图片使用，挂面图片同时供菜谱里的“面条”使用。

第三批用户图片包括茄子、黄瓜、西葫芦、苦瓜和长豆角，均从原图抠出并加白边，分别映射到同名蔬菜。

荷兰豆图片同样从用户提供的原图抠出并加白边，单独映射到“荷兰豆”，不会与长豆角混用。

牛肉和鸡腿肉图片分别映射到肉类同名食材；鸡腿肉新增了煎、炖、红烧和蘑菇炒的菜谱，牛肉增加了洋葱炒和青椒炒菜谱。

可乐与鸡翅图片分别映射到饮料和肉类；可乐截图只裁取罐身。可乐示例使用“罐”作为单位，旧版示例中的“瓶”会迁移到“罐”，手动录入的瓶装可乐仍可用于可乐鸡翅的库存匹配。

`assets/dishes/` 收录用户提供的小炒牛肉、清炒荷兰豆、油焖大虾、肉末豆腐和鱼香肉丝菜品照片。每张图保留整只盘子，去除外部背景并加手绘风白边；这些图片用于烹饪结果、周计划和菜谱详情。鱼香肉丝按用户指定的芹菜、黑木耳、五花肉、胡萝卜配料录入。新增的可乐鸡翅、西红柿炒蛋、肉末豆角、酸辣土豆丝、青椒肉丝和清炒西兰花也使用用户提供的整盘照片，以椭圆盘沿抠图并加白边；这些菜和上一批新菜均进入一周食谱候选。

首次打开新版页面时，系统会将图片示例食材补入仓库，并保留已有库存；已有浏览器数据也会执行一次补入。之后手动删除的示例不会因刷新而重新出现。

## 开发流程

1. 需求确认：确定食材仓库、图片识别、临期提醒、AI 烹饪和一周食谱范围。
2. 信息架构：以食材仓库为默认入口，设置四个核心功能页面。
3. 数据建模：建立食材、菜谱、收藏、历史记录和周计划数据结构。
4. 核心开发：实现库存增删改查、筛选、日期计算和 localStorage。
5. 智能逻辑：实现库存匹配、临期优先、今日采购建议与菜谱评分。
6. 视觉设计：采用家庭生活感的米白与绿色配色，完成响应式布局。
7. 验证优化：检查 JavaScript 语法、页面加载、桌面和移动端布局。

## 运行方式

### 方式一：纯前端（离线单机）

直接双击 `index.html` 即可运行。如果浏览器扩展或本地文件策略影响加载，也可以在当前目录启动静态服务器：

```powershell
python -m http.server 4173
```

然后在浏览器中访问 `http://127.0.0.1:4173/`。此模式下数据只保存在当前浏览器。

### 方式二：前端 + Node 后端（支持登录与云端同步）

后端使用 **Express + MySQL 8.0 + JWT + bcrypt**，数据库为结构化的 11 张表，按 `user_id` 严格隔离。

**首次配置 MySQL（一次性）：** 用有建库权限的账号（如 root）执行，创建专用库和权限受限的账号（不要把 root 密码写进项目）：

```sql
CREATE DATABASE IF NOT EXISTS freshcook CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'freshcook_app'@'localhost' IDENTIFIED BY '你的专用密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, REFERENCES ON freshcook.* TO 'freshcook_app'@'localhost';
FLUSH PRIVILEGES;
```

**配置连接：** 复制 `.env.example` 为 `.env`，填入上面创建的账号密码与 `JWT_SECRET`。`.env` 已加入 `.gitignore`，不会提交。服务启动时会自动创建 11 张表（幂等，可重复运行）。

**运行：**

```powershell
npm install
npm start
```

然后访问 `http://localhost:3000`（后端同时托管静态页面和 API）。点击左下角头像注册或登录，登录后食材、收藏、周计划、家庭动态和 FoodHub 数据会同步到 MySQL，可在不同设备间使用；未登录时行为与纯前端模式一致。

**数据库表（11 张）：** `users`、`ingredients`、`family_activity`、`favorites`、`history`、`generated_recipes`、`week_plan`、`shopping_checked`、`user_state`、`foodhub_posts`、`foodhub_comments`。业务数据均关联 `user_id`，按账号隔离；外键 `ON DELETE CASCADE` 负责清理账号数据。

后端 API：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/health` | GET | 健康检查 |
| `/api/auth/register` | POST | 注册，返回 JWT |
| `/api/auth/login` | POST | 登录，返回 JWT |
| `/api/state` | GET | 读取当前用户的云端数据（需 Bearer Token） |
| `/api/state` | PUT | 保存当前用户的云端数据（需 Bearer Token） |

数据按 `user_id` 严格隔离，密码使用 bcrypt 哈希，JWT 密钥可通过环境变量 `JWT_SECRET` 覆盖（生产环境务必设置）。可选环境变量：`PORT`（默认 3000）、`CORS_ORIGIN`（逗号分隔的允许来源）。

GitHub 仓库保存的是代码，不会自动运行 Node.js 或 MySQL。只打开静态页面时，登录同步接口不可用，仍可使用浏览器本地数据。`data/`、`node_modules/` 和 `.env` 均不会上传；其中 `data/` 是本机旧数据目录，请自行保留或备份。

运行测试（后端 API 测试需先配置好 `.env` 并确保 MySQL 服务已启动）：

```powershell
npm test
```

其中 `cooking-match.test.js` 不依赖数据库，可离线运行；`server-api.test.js` 会在 MySQL 中创建并清理临时测试用户，验证注册、登录、数据读写与跨用户隔离。

## 图片识别说明

照片导入会在浏览器本地分析白底图片的颜色与外形，给青椒、西红柿、胡萝卜、橙子等提供候选名称；不能可靠判断的图片会留空名称，由用户填写。用户需核对名称、数量、存储位置与到期日期后确认入库。系统会去除连通的白色背景、裁出食材主体，并在透明图外加白色贴纸边；同名食材入库时合并为一条并优先使用新上传的图片；处理后的图片随食材保存在浏览器本地，不需要上传服务器或配置密钥。此方法仅适合清晰的白底单品照片，不能替代通用图像识别模型。烹饪推荐基于本地菜谱库和确定性匹配，水果奶昔与水果拼盘由所选食材在本地组合。文字补充要求支持食材名、忌口、少油、不辣、汤/面等类型、分钟限制及只用现有食材；无法识别的要求会在结果中说明。匹配时至少要用到所选食材；已过期食材不会计入可用库存。菜谱以两人份为基准，结果页会按用餐人数及可用库存调整食材用量，小份会明确标注。

勾选更多食材不会提高最低命中门槛；会优先推荐使用更多所选食材、库存足量且符合时间的菜谱。全部主食材都有库存时，可缩小菜谱份量；例如 1 个鸡翅和 1 罐可乐可制作一份小份可乐鸡翅，记录完成时仅扣减实际建议用量。找不到已有菜谱时，常见的肉、蛋、豆腐和蔬菜搭配会生成有明确步骤的本地建议。缺少某种主食材、过期或超时仍不会当作可以直接完成；菜谱库和本地搭配都无法覆盖时才会显示本地无匹配。

## 数据重置

如需恢复初始演示数据，可在浏览器开发者工具中执行：

```javascript
localStorage.removeItem("foodmind-state-v1");
location.reload();
```
